## 1. 目标与里程碑

**目标**：一个装着我本人音色、我本人说话方式的离线桌面宠物，全本地推理，不依赖云 API。

| 里程碑 | 内容 | 整体完成判定 | 截止 |
|---|---|---|---|
| **M1** | 文字对话 + 我的音色，端到端一条链 | 打字 → 出字 → **我的音色**读出来，连续 5 轮不崩，回复无思考链、无编造 | 2026-11-01（周日） |
| **M2** | 可演示桌宠 | 双击启动 → 透明置顶桌宠 → 提问 → 我的音色回答 + 嘴动 → 60 秒演示视频 | 2026-11-12（周四） |

M1 只要「通」，M2 要「像」和「好看」。

**进度修正（v0.2）**：文字对话、桌宠窗口、埋点、口型已经在 10/29 跑通，比我原排期早 2 天。M1 剩余工作量集中在**换音色 + 内容质量 + 重录音**三件事，不在界面。

**在范围内**：文字对话（单轮 + 20 轮）、我的音色 TTS、桌宠窗口与口型、ASR、打断、人格角色卡、延迟埋点、隐私闸门、Release 与回滚。

## 4. 用户场景（验收照着演）

- **S1**：我打字「今天想干点啥」，1 秒内出字，回复不超过 3 句，用我的音色读完。
- **S2**：连聊 20 轮，第 20 轮还能接上第 1 轮的事，且不复读同一句。
- **S3**：我问「你是不是 AI」，它如实承认是本地模型，不装人。
- **S4**：它说话时我开口，半秒内闭嘴（M2）。
- **S5**：我双击图标，桌宠出现在桌面；别人从电脑或仓库里看不到我的任何个人数据。

**R4b 音色相似度** · @周 · 基线已给

- 指标：3D-Speaker CAM++ 192 维（sherpa-onnx 1.13.8，CPU）余弦。
- **基线【实测，@周 2026-10-29】**：同人 66 对 → 中位 0.686 / p5 0.532 / 最小 0.448；异人（vs 公开样本）→ 中位 0.205 / 最大 0.348。
- **验收：合格 ≥ 0.45、目标 ≥ 0.55**（采纳 @周 建议值，落在 0.348 与 0.448 之间的空档）。
- **限定条件必须写进结论**：该基线是在 **22.9 dB 噪声底**上测的，噪声压低同人分；重录后同脚本重跑，阈值**可能上移**，届时以重录基线为准，我改本表，不提前锁定。
- 主观轨：3 名听者盲听，真人原声与合成各 5 句，≥ 2/3 判「同一人/很像」。两条都要过。

**R6 录音素材合格** · @周 · 需重录

> **v0.1 的错，我改**：我写了「40 条一条没录」，**这条是错的**。@周 用 whisper-large-v3-turbo 转写核验，那个 10 分 38 秒车内录音**就是 40 条脚本本体、每句念 2 遍**，40 条都有时间锚点，28 条字符覆盖率 ≥0.85（其余 12 条是 ASR 用词差异）。**真实缺陷是环境不合格，不是素材缺失。** 结论和排期影响都已改。

- **实测（638.29 s，48 kHz 单声道 AAC）**：帧级底噪 **-39.4 dBFS**（合格线 ≤ -55，不合格）；活动帧 p90 -16.5 → **SNR 22.9 dB**（合格线 ≥ 35，不合格）；峰值 **+0.80 dBFS**、23 个样本削波，但**只集中在 375–386 s 的一次爆音**，剔掉即可；底噪漂移 7.9 dB、语音电平漂移 9.0 dB；0–300 Hz 比 1–3.4 kHz 高 10–12 dB（路噪轰鸣）。
- **内容核验通过**：pyannote-3.0 + CAM++ 聚类 → 主簇 285.8 s（95.5%），三个碎片簇与主簇余弦 0.694/0.795/0.767（同人水平）→ **单人、无第二说话人**；频谱无谐波带、无节拍 → **无音乐**。所以 M1 **不必**降级成「随便找段音频出声」。
- **可用素材 185 s（24 块，最长 22 s）** → 够训一版「只求出声」的 M1 实验音色。
- 重录三条硬指标：室内关空调关窗；嘴距 15–20 cm 不手持；**输入增益降 6 dB**（目标峰值 ≤ -6 dBFS，本次削掉的部分不可恢复）。
- 自动验收判据：底噪 ≤ -55 dBFS、SNR ≥ 35 dB、峰值 ≤ -6 dBFS、削波样本 0、底噪漂移 ≤ 3 dB、语音电平漂移 ≤ 6 dB。
- 交付路径统一：质检报告进 `~/Desktop/我的数字人/voice-report/`（**不进公开仓**）。我 v0.1 写 `录音/QC-*.md` 是我写错了，按 @周 的目录约定执行。

**R15（新增）system 固定 / 前缀缓存不许回退** · @郑 / @吴 · **已达成，升为回归门禁**

- 背景【实测，@郑】：一开始把真实时间写进 `system`，每轮 system 都变 → ollama 的 KV 前缀缓存整段失效，每轮重算 500→870 token，首字从 168 ms 涨到第 20 轮 **1606 ms**。改成「system 固定 + 时间贴在用户消息末尾」后同一套 20 轮：首字 P50 **866 → 282 ms**、端到端首音 P50 **1892 → 1056 ms**。
- 判据：① 20 轮里实际下发的 system 文本 sha256 **恒定**；② 每轮 `prompt_tokens` 增量 ≤（上轮用户消息 + 回复）token × 1.3；③ 首字 P95 ≤ 500 ms。任一不满足即判回归。

**R16（新增）运行时时间注入** · @吴 / @郑 · 已达成

**R8 人格角色卡** · @吴 · v4 已出，3 类缺陷

- 判据：20 题（含 5 条钓鱼题）≥ 16 条符合硬规则。

  1. **复读**：20 轮内同一句 ≥4 字的回复出现次数 ≤ 2。（实测「睡吧，天还早」出现 3 次：第 2、7、13 轮，违反「同一句话不说两遍」。）
